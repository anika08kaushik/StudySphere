3. Clone the Repository

Clone the repository:

git clone https://github.com/anika08kaushik/StudySphere.git

Enter the project:

cd StudySphere
4. Switch to the Development Branch

Do NOT develop directly on main.

The shared development branch is:

develop

Switch to it:

git switch develop

Pull the latest changes:

git pull origin develop

Branch structure:

main
  ↑
develop
  ↑
feature/<your-feature>
5. Install Dependencies

From the project root:

npm install

The project is configured so the frontend and backend dependencies can be managed from the root.

Normally, you do NOT need to run npm install separately inside frontend and backend.

If necessary, dependencies can be installed individually.

Frontend
cd frontend
npm install
Backend
cd ../backend
npm install

Return to the project root:

cd ..
6. Environment Variables

StudySphere uses separate environment files for the frontend and backend.

Environment files contain local configuration and sensitive credentials.

IMPORTANT

Never commit:

.env
.env.local

to GitHub.

The repository contains .env.example files showing the required variables.

7. Frontend Environment

Create:

frontend/.env

Add:

VITE_API_URL=http://localhost:5000/api

This tells the React application where the StudySphere backend API is running.

8. Backend Environment

Create:

backend/.env

Add:

PORT=5000

MONGO_URI=YOUR_MONGODB_CONNECTION_STRING

JWT_SECRET=YOUR_LOCAL_JWT_SECRET

CLIENT_URL=http://localhost:5173

Ask the project owner/team lead for the development MongoDB access details.

Never commit the actual values to GitHub.

9. MongoDB Atlas Setup

StudySphere uses MongoDB Atlas as the development database.

Development database:

studysphere-dev

The backend connects to MongoDB using:

MONGO_URI

inside:

backend/.env

Example structure:

MONGO_URI=mongodb+srv://USERNAME:PASSWORD@CLUSTER.mongodb.net/studysphere-dev

The actual credentials must remain private.

Do NOT put MongoDB credentials in:

GitHub
README.md
REQUIREMENTS.md
.env.example
Source code
Screenshots
Public documentation
10. Verify MongoDB Connection

After configuring:

backend/.env

run:

cd backend
npm run seed

A successful setup should display:

MongoDB connected
Seed data created done

Return to the project root:

cd ..

The seed script creates development/test data.

IMPORTANT

The seed script is for development only.

Never run the seed script against a production database.

11. Start the Application

From the project root:

npm run dev

This starts both the frontend and backend development servers.

Expected:

Frontend:
http://localhost:5173

Backend:
http://localhost:5000
12. Verify the Backend

Open:

http://localhost:5000/api/health

Expected response:

{
  "success": true,
  "message": "StudySphere API is running"
}

If this response appears, the backend is running correctly.

16. Protected Document System

The protected document system is one of StudySphere's main differentiating features.

The objective is to ensure that shared academic documents are accessed through StudySphere rather than through publicly accessible file URLs.

Flow:

Upload Document
      ↓
Private Cloud Storage
AWS S3 / Firebase
      ↓
NO PUBLIC FILE URL
      ↓
MongoDB Metadata
      ↓
StudySphere API
      ↓
Authorization Check
      ↓
┌───────────────┴───────────────┐
│                               │
▼                               ▼
AUTHORIZED USER          UNAUTHORIZED USER
│                               │
▼                               ▼
ACCESS GRANTED                 DENIED
│
▼
StudySphere Viewer
│
├── View Document
├── Page Navigation
├── Search
├── Zoom
├── Dynamic Watermark
├── Access Tracking
└── Audit Logging

Access control uses:

JWT Authentication
        +
Study Group Membership
        +
Role Permissions
        +
Document Permissions

Unauthorized users:

ACCESS DENIED

Authorized users:

STUDYSPHERE VIEWER
